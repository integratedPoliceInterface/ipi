================================================================================
        RELATÓRIO TÉCNICO-COMERCIAL — IPI
        Interface Policial Integrada (PMGO / SSP-GO)
================================================================================

1. VISÃO GERAL
--------------------------------------------------------------------------------
O IPI é um aplicativo tático de campo offline-first desenvolvido para a Polícia
Militar de Goiás (PMGO), com foco no patrulhamento rural. Permite que policiais
em campo consultem veículos e pessoas, registrem ocorrências (RAI) e acessem
mapas offline do estado de Goiás — tudo em um único dispositivo móvel,
operando mesmo sem conexão com a internet.


2. STACK TECNOLÓGICA
--------------------------------------------------------------------------------
  Camada            | Tecnologia                           | Função
  ------------------+--------------------------------------+---------------------------
  Runtime           | Vanilla JavaScript ES6+ + HTML5+CSS3  | App inteiro sem framework
  Mobile            | Capacitor 5 (Android/iOS)             | Wrapper nativo
  Mapas Offline     | Leaflet + Protomaps + PMTiles         | Mapas vetoriais offline
  Banco Local       | SQLite (sql.js / capacitor-sqlite)    | Criptografado AES-256-CBC
  Criptografia      | PBKDF2 + SHA-256 + Web Crypto API     | 100k iterações
  Cloud             | Supabase (PostgreSQL + REST API)      | Backend central
  Serialização      | Protocol Buffers (protobufjs)         | ~60% economia de banda
  SMS               | Plug-in Capacitor + fallback sms:     | Modo degradado
  Deploy            | Vercel (static hosting)               | Frontend estático

Diferencial: Zero frameworks frontend. Arquitetura deliberadamente leve para
performance máxima em dispositivos de baixo custo usados por policiais em campo.


3. ARQUITETURA (OFFLINE-FIRST)
--------------------------------------------------------------------------------
  [App] -> Serviços -> SQLite Criptografado <-> Supabase
          |
  Gerenciador de Conectividade
  (NUVEM | SMS | APAGÃO)


3.1 Três Modos de Operação (Fallback Automático)
--------------------------------------------------------------------------------
  Modo     | Falhas     | Funcionalidades
  ---------+------------+--------------------------------------------------------
  NUVEM    | 0 falhas   | Tudo online: Supabase, mapas OSM, rotas OSRM
  SMS      | 1 a 5 falh | Consultas via SMS, RAIs salvos localmente, mapas online
  APAGÃO   | 6+ falhas  | Local-only: SQLite offline, PMTiles, cache suspeitos

Verificação automática a cada 20 segundos contra URL configurável. Transição
invisível para o usuário.


4. FUNCIONALIDADES PRINCIPAIS
--------------------------------------------------------------------------------

4.1 Registro de Ocorrência (RAI)
  - 9 tipos de ocorrência (Furto, Roubo, Homicídio, Tráfico, etc.)
  - Captura automática de GPS
  - Vinculação de pessoas (Suspeito, Vítima, Testemunha, Autor) e veículos
  - Observações livres
  - Sincronização imediata se em NUVEM, queue local se offline

4.2 Consulta de Veículos
  - Por placa (ex: ABC1D23)
  - Origem: Supabase (NUVEM) -> SQLite+SMS (SMS) -> SQLite (APAGÃO)
  - Destaque em vermelho para veículos ROUBADO / FURTADO / QUEIXADO

4.3 Consulta de Pessoas
  - Por CPF (auto-detecção de 11 dígitos) ou nome
  - Três situações: REGULAR, MANDADO_PRISAO, FICHA_CRIMINAL
  - Dados: nome, CPF, data nascimento, mandado, observação

4.4 Mapas Offline (Goiás)
  - Leaflet + PMTiles do estado inteiro armazenados localmente
  - Busca offline por 246 municípios goianos (hardcoded com coordenadas)
  - Rotas OSRM online / linha reta offline
  - Ícone do policial com localização atual

4.5 Sincronização Automática
  - A cada 15 segundos em modo NUVEM
  - Push de RAIs pendentes serializados em Protobuf (~60% menor que JSON)
  - Pull de RAIs de outros operadores no mesmo município de missão
  - Badge com contagem de pendentes + toast de notificação

4.6 Segurança
  - Banco SQLite criptografado AES-256-CBC
  - Chave derivada do PBKDF2 (100k iterações) a partir da matrícula do operador
  - Re-key automático no login/logout (troca chave do operador para anônima)
  - Autenticação via Supabase com senha hasheada (salt:hash em PBKDF2)


5. REGRAS DE NEGÓCIO
--------------------------------------------------------------------------------
  RN-001  RAI só pode ser salva se tipo e descrição (>= 10 caracteres) preenchidos
  RN-002  Matrícula do operador é vinculada automaticamente a cada RAI
  RN-003  ID da RAI = RAI-{timestamp_unix}
  RN-004  Sincronização só ocorre se modo = NUVEM
  RN-005  Cache local armazena apenas veículos/pessoas não-REGULARES
  RN-006  Pull de RAIs no sync ignora RAIs do próprio operador
  RN-007  Alternância automática entre os 3 modos de conectividade
  RN-008  Município de missão filtrável — cache e pull restritos a ele


6. HISTÓRIAS DE USUÁRIO
--------------------------------------------------------------------------------

US-001: Login Offline
  "Como policial em campo, quero acessar o sistema com minha matrícula e senha
   mesmo sem internet, para poder registrar ocorrências no local da ocorrência."
  Critério: Autenticação via PBKDF2 contra Supabase, fallback para sessão local.

US-002: Consulta Veicular em Área Rural
  "Como policial na zona rural de Goiás, quero consultar a placa de um veículo
   suspeito onde não há sinal de internet, para verificar se é roubado."
  Critério: Consulta em APAGÃO via cache local; se em SMS, envia SMS para
  central; retorno com situação do veículo.

US-003: Registro de Ocorrência com GPS
  "Como policial atendendo uma ocorrência, quero registrar o RAI com coordenadas
   GPS automáticas e vincular pessoas/veículos envolvidos."
  Critério: Captura de localização, formulário com tipo, descrição, envolvidos,
  sincronização transparente.

US-004: Mapa Offline do Estado
  "Como policial sem internet, quero acessar o mapa de Goiás offline para me
   localizar durante deslocamentos em áreas remotas."
  Critério: PMTiles armazenado localmente, busca por municípios, ícone de
  localização atual.

US-005: Sincronização Automática
  "Como chefe de operação, quero que os RAIs da minha equipe sejam sincronizados
   automaticamente quando houver conexão, sem ação manual."
  Critério: Sync a cada 15s, push de pendentes via Protobuf, pull de RAIs de
  outros operadores.


7. BANCO DE DADOS (SQLite Local + Supabase Cloud)
--------------------------------------------------------------------------------
  Tabela               | Descrição
  ---------------------+--------------------------------------------------
  policiais            | Operadores (matrícula, nome, senha_hash, unidade)
  ocorrencias          | RAIs (id, tipo, descrição, GPS, operador, sync)
  veiculos             | Veículos (placa, modelo, cor, ano, situação)
  pessoas              | Pessoas (CPF, nome, data_nasc, situação, mandado)
  envolvidos           | Relaciona pessoas a ocorrências
  veiculos_envolvidos  | Relaciona veículos a ocorrências
  configuracoes        | Chave-valor para configurações locais
  mapa_offline         | Armazena bytes do PMTiles do mapa de Goiás

Regras de cache:
  - Veículos e pessoas com situação != REGULAR são baixados para cache local
  - Cache filtrável por município de missão
  - RAIs pendentes (sincronizado=0) são enfileirados para sync


8. POTENCIAL DE EVOLUÇÃO (ROADMAP)
--------------------------------------------------------------------------------
  1. Biometria — Login com impressão digital / facial
  2. Notificações Push — Alertas de veículos e pessoas procuradas em tempo real
  3. Modo Rádio (VHF) — Comunicação alternativa via rádio digital
  4. Integração com Denúncia Online — RAI puxado de denúncia 190
  5. Dashboard de Comando — Visão do comandante com RAIs em tempo real
  6. Multi-idioma — Suporte a espanhol/inglês para operações de fronteira
  7. Relatórios Automáticos — PDF exportável do RAI


9. MÉTRICAS DE IMPACTO
--------------------------------------------------------------------------------
  - Zero dependência de internet: operação garantida em 100% do território
  - Economia de ~60% de banda via Protobuf (comparado a JSON)
  - Setup zero: app auto-contido, sem infraestrutura local
  - Criptografia de ponta a ponta: dados protegidos mesmo se dispositivo perdido
  - Custo operacional mínimo: apenas Supabase + Vercel
